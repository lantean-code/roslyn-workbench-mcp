# Generated-source policy

Approved for implementation as roadmap item 8.

## Purpose

Roslyn Workbench must prevent accidental edits to deterministic build outputs while recognising that repositories sometimes check generated source into version control and intentionally maintain or regenerate it. This policy protects against agent mistakes and unexpectedly broad transformations; it does not treat the connected authorised MCP client as a hostile tenant.

## Classification boundary

The existing hard denials remain unchanged. Actual Roslyn source-generated documents are outside the ordinary addressable source collection, while regular source beneath an `obj` path, external documents and non-source inputs cannot enter the mutation pipeline.

The new policy applies only to regular, physically contained, checked-in source that appears generated. A shared classifier recognises case-insensitive `.g.cs`, `.g.i.cs`, `.generated.cs` and `.designer.cs` suffixes, `TemporaryGeneratedFile_` names, and `<auto-generated` or `<autogenerated` markers within the first 2,048 characters of source. Header inspection is bounded and runs only for changed documents or for a query that explicitly requests generated-source exclusion.

Repository-specific exceptions are Workspace-relative simple wildcard patterns supporting `*` and `?`. They are evaluated using the effective filesystem case sensitivity. Absolute patterns and patterns containing `.` or `..` path segments fail startup validation. An exception removes the matching path from generated-looking classification; it does not bypass containment, source-kind or intermediate-output denials.

## Operator policy

`--generated-source-policy warn|deny` selects an immutable startup policy and defaults to `warn`. `ROSLYN_WORKBENCH_MCP_GENERATED_SOURCE_POLICY` is the environment equivalent, with command-line configuration taking precedence.

`--generated-source-exception <pattern>` is repeatable. Its environment equivalent, `ROSLYN_WORKBENCH_MCP_GENERATED_SOURCE_EXCEPTIONS`, uses the platform path separator. If any command-line exception is present, the complete command-line list replaces the environment list.

`warn` stages generated-looking source normally and emits one bounded structured warning. The same warning is recalculated from the complete active transaction during preview. Approval-required review classifies each exact persistence entry as `project-source` or `generated-looking-source`, binds that classification into the receipt digest, and emits the bounded warning.

`deny` rejects a candidate before it can be staged when a changed path remains generated-looking after exceptions. The error identifies the first canonical Workspace-relative path and directs the operator to configure an exception and restart only when that checked-in source is intentionally maintained.

No silent allow mode is provided. An exception is the explicit way to acknowledge a repository convention while retaining the hard mutation boundary.

## Query consistency

Bundled queries that offer generated-source exclusion use the same classifier and exception list. This prevents mutation policy and query filtering from maintaining separate filename rules. Queries remain read-only and do not apply the mutation policy's `warn` or `deny` decision.

## Interaction model

Generated-source policy does not introduce elicitation. It is deterministic startup-owned configuration: `warn` supplies review evidence and `deny` rejects the operation. Transactional commit confirmation and receipt-bound approval continue to provide the mode-specific user-authorisation boundary without an additional prompt whose answer could conflict with the configured policy.

## Verification

Unit coverage exercises every filename convention, both header markers, bounded header inspection, case-sensitive and case-insensitive exceptions, validation, added/changed/removed and linked documents, warning bounds, warn/deny staging behaviour, query filtering, preview warnings and receipt classification. Host configuration and status tests cover defaults, command-line and environment precedence, invalid values and the non-sensitive exception count.
