    Transaction Start

    transaction-start · Mutation · Server · Transactions

    Starts a new staged transaction. Check workspace-status first and do not mutate a workspace that is or may be in use elsewhere unless mutation ownership has been coordinated.

    Availability: Published in transactional, approval-required and autonomous-trusted operational modes.

    Generated from Roslyn Workbench MCP 1.0.0 (1.0.0).

    Behaviour annotations

    Annotation Value
    destructiveHint false
    idempotentHint false
    openWorldHint false
    readOnlyHint false
    title "Transaction Start"

    Request

    Property Type Required Description
    workspace object | null No Provide workspaceId, alias, path, or any combination.

    Response

    Success response

    Property Type Required Description
    ok boolean constant (true) Yes Whether the tool invocation succeeded.
    data object | null Yes Tool-specific result payload.
    snapshot object No Exact immutable workspace snapshot associated with the result, when available.
    warnings array No Non-fatal warnings the agent should consider.

    Error response

    Property Type Required Description
    ok boolean constant (false) Yes Whether the tool invocation succeeded.
    error object Yes Structured error details when the invocation failed.
    continuation oneOf No Action the agent should take before retrying or continuing.
    diagnostics array No Diagnostics that explain the failed invocation.
    warnings array No Non-fatal warnings the agent should consider.

    Error response

    Property Type Required Description
    ok boolean constant (false) Yes Whether the tool invocation succeeded.
    error object Yes Structured error details when the invocation failed.
    diagnostics object Yes Diagnostics that explain the failed invocation.
    reporting object No Error-reporting workflow available for an unhandled failure.

    Continuations and required actions

    A response may include a structured continuation at the following schema location. Follow its tool call or user-action instruction instead of guessing how to continue:

    • $/oneOf/1/properties/continuation

    Examples

    Start a transaction

    Workflow: Stage, review and commit one change, step 1.

    Operational modes: transactional, autonomous-trusted.

    Create an isolated staging area before invoking a mutation or Code Action.

    Expected outcome: The sample workspace owns a new transaction at its initial revision.

    {
  "workspace": {
    "alias": "sample"
  }
}

    Start a transaction for the Code Action

    Workflow: Discover and stage a Code Action, step 1.

    Operational modes: transactional, autonomous-trusted.

    Create the transaction that will receive the selected Code Action changes.

    Expected outcome: The sample workspace owns a new transaction at its initial revision.

    {
  "workspace": {
    "alias": "sample"
  }
}

    Start the approval-required transaction

    Workflow: Review an exact change for one-use approval, step 1.

    Operational modes: approval-required.

    Create the transaction whose exact persistence set will later receive one-use approval.

    Expected outcome: The sample workspace owns a new transaction at its initial revision.

    {
  "workspace": {
    "alias": "sample"
  }
}
